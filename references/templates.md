# SKILL.md のひな型（穴埋めで使う）

作るときに開く。**クイックコース＝最小形**、**匠コース＝フル形**を使う。
各欄に「なぜこの欄があるか」を書いてあるので、**理由が当てはまらない欄は消してよい**（意味のない空欄を残すと、AIがそこを埋めようとして迷います）。

---

## 用語の言い換え（このファイルを読む前に）

- **フロントマター**：ファイルの一番上、`---` で挟まれた部分。**本の表紙**にあたるところ。AIはまずここを見て「このスキルを使うべきか」を判断します
- **本文**：表紙の下、実際の手順を書くところ。AIが「使う」と決めたあとに読まれます
- **references（リファレンス）**：本文が長くなったときに中身を逃がす別部屋。**必要になったときだけ**読まれるので、本体が軽く保てます

---

## ひな型A：最小形（クイックコース用）

そのままコピーして、`〈 〉`の中を書き換える。

```markdown
---
name: 〈半角小文字とハイフンだけ。フォルダ名と同じにする。例：weekly-report〉
description: 〈何をするスキルか（1文）〉。「〈実際に打つ頼み方1〉」「〈頼み方2〉」「〈頼み方3〉」のように言われたら必ず使うこと。〈仕上がりの特徴を1文〉
---

# 〈スキルのタイトル（日本語でよい）〉

〈このスキルが誰の何を楽にするか、2〜3行〉

## 手順

1. 〈最初にすること〉（理由：〈なぜそうするか〉）
2. 〈次にすること〉（理由：〈なぜそうするか〉）
3. 〈最後にすること〉（理由：〈なぜそうするか〉）

## 出力の型

〈完成品のフォーマットをそのまま貼る。見本があるなら見本をそのまま置くのが一番速い〉

## 合格ライン（これを満たしたら完成）

- [ ] 〈聞き取りで出た「一番大事なこと」をそのまま1つ〉
- [ ] 〈2つめ〉
- [ ] 〈3つめ〉

## やってはいけないこと

- 〈過去に実際にやらかした失敗を、そのまま禁止事項として書く〉
```

**※ 商品名・日付・金額など、毎回変わる部分は `〈商品名〉` のように置き換えて書く**（理由：実物の値をそのまま残すと、次に使ったときも同じ値が出てきてしまうためです）。

**各欄の意味**

| 欄 | なぜあるか |
|---|---|
| `name` | ファイルの住所。フォルダ名とずれると読み込まれません |
| `description` | **発動率の9割がここで決まる。** 実際に打つ頼み方をそのまま2〜4個入れる |
| 手順（理由つき） | 理由があるとAIが応用できる。理由の無い指示は例外が来た瞬間に壊れます |
| 出力の型 | 「いい感じに」では毎回違う物が出る。形を見せると形が揃います |
| 合格ライン | 聞き取りで出た「これができていれば合格」の置き場所。**動かして点検するときに、1項目ずつ○×で突き合わせる基準**になります |
| やってはいけないこと | 過去の失敗を潰す欄。ここが一番効きます |

## ひな型B：フル形（匠コース用）

```markdown
---
name: 〈半角小文字とハイフン。フォルダ名と同じ〉
description: 〈何をするスキルか（1文）〉。ユーザーが「〈頼み方1〉」「〈頼み方2〉」「〈頼み方3〉」「〈頼み方4〉」のように言ったら必ず使うこと。〈対象範囲・仕上がりの特徴〉。〈似た別スキルがあるなら、そちらに回す条件を1文〉
---

# 〈スキルのタイトル〉

〈一行定義：誰の・どんな困りごとを・どう楽にするか〉

〈前提・むいている場面／むいていない場面〉

## 進め方

### 1. 〈段階の名前〉
〈やること〉（理由：〈なぜ〉）

確認すること：
- 〈項目〉
- 〈項目〉

### 2. 〈段階の名前〉
〈やること〉（理由：〈なぜ〉）

### 3. 〈段階の名前〉
〈やること〉（理由：〈なぜ〉）

## 判断ルール（分かれ道）

| 場面 | どうするか | 理由 |
|---|---|---|
| 〈条件〉 | 〈対応〉 | 〈理由〉 |
| 〈条件〉 | 〈対応〉 | 〈理由〉 |

## 出力の型

〈完成品のフォーマット。長い見本は references/ に逃がす〉

## 合格ライン（これを満たしたら完成）

- [ ] 〈項目〉
- [ ] 〈項目〉
- [ ] 〈項目〉

## やってはいけないこと

- 〈過去の失敗から〉
- 〈渡してはいけない情報があるならここに〉

## 参考ファイル（いつ読むか）

- `references/〈ファイル名〉.md` — 〈どんなときに読むか〉
```

**フル形だけにある欄の意味**

| 欄 | なぜあるか |
|---|---|
| むいている／むいていない場面 | 守備範囲の外で無理に使われると品質が落ちる。先に線を引く |
| 判断ルールの表 | 「場合による」部分を放置すると、AIが毎回違う判断をします |
| 合格ライン（チェックボックス） | 自走検証ループ（工程⑥）で1項目ずつ突き合わせる基準になります |
| 参考ファイル | 本文を軽く保つため。本文からの案内が無いと、置いても読まれません |

## マルチAI対応：書き分けの一覧

SKILL.md の形式は Anthropic が開発した**オープンな規格**（Agent Skills）で、**2026年8月時点で40を超えるツール**が対応をうたっています（Gemini CLI、Cursor、GitHub Copilot、VS Code など）。OpenAI の Codex も公式に対応しています。

ただし、**同じファイルでもツールによって読み込みの挙動は異なります**（規格の公式説明でも明記されています）。だから書き分けます。

### 表紙（フロントマター）に書いてよいもの

| 書けるもの | どこまで安全か |
|---|---|
| `name` | どのツールでも必須級。**両対応版でも必ず書く** |
| `description` | 同上。**発動の判断がここで行われる** |
| `license` / `compatibility` / `metadata` | 規格に含まれる補助項目。両対応版で使ってよい |
| `allowed-tools` | **両対応版では使わない。** 規格上まだ実験的な扱いで、ツールによって対応が違います |

### Claude Code だけが解釈するもの（両対応版では使わない）

ほかのツールでは無視されるか、環境によってはエラーになります。

`when_to_use` / `argument-hint` / `arguments` / `disable-model-invocation` / `user-invocable` / `disallowed-tools` / `model` / `effort` / `context`（fork） / `agent` / `background` / `hooks` / `paths` / `shell`

本文中の `` !`コマンド` `` という書き方（コマンドの実行結果を埋め込む記法）も同じく Claude Code 専用です。

### Codex で使う場合の注意

Codex は同じ SKILL.md を読みますが、実際に見ているのは**ほぼ `name` と `description` だけ**で、それ以上の設定は別ファイル（`agents/openai.yaml`）に書く方式です。
つまり「**Codexでも動く**」は言えますが、「**Claude Code 向けに書いた細かい指定までそのまま効く**」わけではありません。手順の中身は、本文の日本語の指示で成り立つように書いてください。

### 両対応版の書き方チェック

- [ ] 表紙は `name` と `description`（＋必要なら `license` / `compatibility` / `metadata`）だけになっているか
- [ ] 手順の中身が、本文と `references/` の**ふつうのテキスト**だけで成立しているか
- [ ] 特定のツールにしかない機能に手順が依存していないか（使うなら「使える環境なら」と条件つきで書く）
- [ ] パスをOSに縛っていないか（`\Users\`で始まるWindowsの絶対パスや `/Users/`・`/home/` を手順に埋め込まない）

> **必ず伝える注意**
> ツールごとに読み込みの挙動が違います。**動作検証は、あなたが実際に使うAIで、あなたの手で必ず行ってください。**

## 保存場所（迷ったときの早見）

| やりたいこと | 置き場所 |
|---|---|
| どこで作業していても使いたい | `~/.claude/skills/〈スキル名〉/SKILL.md` |
| この仕事のフォルダでだけ使いたい | そのフォルダの `.claude/skills/〈スキル名〉/SKILL.md` |
| 見本や資料を分けたい | 同じフォルダの中に `references/` を作って置く |

※ `~` は「あなたのユーザーフォルダ」のことです。デスクトップや書類フォルダと同じ階層にある、自分の名前がついたフォルダだと思ってください。
※ フォルダ名と `name` は必ず揃えます。ずれていると読み込まれません。

**※ `.claude` は先頭に点が付く「隠しフォルダ」で、普段は画面に出てきません。見つからなくても壊れていません。**

開き方：

- **Windows**：エクスプローラーを開き、上のアドレス欄に `%USERPROFILE%\.claude\skills` と打ってEnter
- **Mac**：Finderを開き、`Command + Shift + G` を押して、出てきた欄に `~/.claude/skills` と打ってEnter

仕事のフォルダ専用に置く場合も同じで、そのフォルダの中に `.claude` という隠しフォルダを作ります（無ければ新規作成してかまいません）。

# 議事録おこし（kaigi-memo）

> **これは「スキル鍛冶」に同梱された見本です（両対応形＝どのAIでも動く書き方の見本）。** そのまま使えますし、自分用に書き換えてもかまいません。

会議の走り書き・箇条書きメモ・文字起こしを、**あとで使える議事録**に整えるスキル。
会議のあとで「で、結局なにが決まったんだっけ」「あれ誰がやるんだっけ」を無くすのが目的です。

**むいている場面**：数人〜十数人の社内会議・定例・打ち合わせ。メモが断片的でも構いません。
**むいていない場面**：一言一句を残す必要がある会議（株主総会・懲戒に関する面談など。逐語録は別物です）。録音そのものからの文字起こし（このスキルは、文字になったものを整える係です）。

## 進め方

### 1. 材料を受け取る

走り書き・箇条書き・文字起こしのどれでも受け取る。**チャットに貼り付けてもらってもよいし、ファイルで渡してもらってもよい**（理由：使う人の環境によって、ファイルを渡せる場合と貼り付けしかできない場合があるため）。

### 2. 足りない情報を先に聞く

議事録の頭に必要な情報のうち、材料から読み取れないものを**まとめて1回で聞く**（理由：作ってから何度も聞き直すと、相手の手が止まるため）。

聞くのはこの4つだけ：会議の名前／開催日／出席者／次回の予定。
**分からないものは、聞いたうえでなお不明なら `〈未記入〉` と書いて先へ進む。** 空欄にはしない。

### 3. 発言を3つの箱に仕分ける

材料を最初から最後まで読み、それぞれの内容を3つに分ける（理由：会議のメモが読み返されないのは、決まったことと雑談が同じ見た目で並んでいるからです）。

- **決定事項**：会議の場で結論が出たこと。「〜することにした」「〜で合意」
- **宿題**：誰かが会議のあとにやること。担当と期日が付くもの
- **持ち越し**：話には出たが結論が出なかったこと。次に持ち越すもの

**どの箱にも入らない話（雑談・経緯の説明）は、書かない。**

### 4. 宿題に担当と期日を付ける

宿題の1件ずつに、担当者と期日を付ける。

材料の中に期日が「来週まで」「今月中」のような**言葉のままで書かれているときは、勝手に日付へ直さない**（理由：会議のどの日を起点にしているかは書いた人にしか分からず、AIが計算した日付は責任の所在がずれた状態で一人歩きするため）。**原文のまま残し、末尾に `〈要確認〉` を付けて、最後の確認リストにも載せる。**

担当が書かれていない宿題は、担当欄を `〈要確認〉` にする。**その場にいた誰かを推測で当てはめない。**

### 5. 出力の型どおりに書き出して、確認リストを添える

下の「出力の型」に沿って書く。最後に、`〈要確認〉` が付いた項目を**もう一度まとめて並べる**（理由：本文に散らばったままだと、忙しい人は見落とすため）。

## 判断ルール（分かれ道）

| 場面 | どうするか | 理由 |
|---|---|---|
| 結論が出たのか曖昧な話 | 決定事項ではなく**持ち越し**に入れる | 決まっていないことを決定事項に書くのが、議事録でいちばん重い事故 |
| **やることは決まったが、担当が決まっていない** | 決定事項に書き、**あわせて宿題にも1件立てて担当を `〈要確認〉` にする** | 決定事項だけに書くと、担当が空いたまま誰の視界にも入らず、次の会議まで放置される |
| **人の仕事ぶりへの評価が出た**（「〜さんの対応が遅い」など） | **書かない。** 決定でも宿題でもないため、3つの箱のどれにも入れない | 議事録は回覧されて残ります。評価の言葉だけが文脈から切り離されて残るのが、いちばん人間関係を壊す |
| 出席者が役職だけで書かれていて、誰か特定できない | `部長〈要確認：氏名〉` のように、役職を残したまま印を付ける | 議事録は社外や後任にも渡ります。「部長」だけでは半年後に誰か分かりません |
| **宿題の担当が、部署名や係名で書かれている**（「経理で対応」「総務にお願い」） | 部署名を残したまま `経理〈要確認：個人名〉` と印を付ける | 部署宛の宿題は、**全員が「誰かがやる」と思って誰もやらない**のが典型です。名前が入るまで宿題は動きません |
| **発言者名の無い文字起こしで、出席者が読み取れない** | 出席者欄を `〈未記入〉` にし、**要確認の一覧に「出席者を確認してください」を必ず1件立てる** | 手順2の `〈未記入〉` は「聞いたが分からなかった」印です。印を置くだけで終わらせると、そのまま配られます |
| **その場にいない人の異論・伝聞が出た**（「〜さんは反対らしい」「欠席の〜から異論が出ている」） | 個人名を書かず、`〈部署・立場〉から異論がある旨` の形にして持ち越しに入れる | 本人が反論できない場に、名指しの反対意見だけが記録として残ります。人の仕事ぶりへの評価を書かないのと同じ配慮です |
| 同じ話が何度も出てくる（文字起こしにありがち） | 1件にまとめ、最後に出た結論を採る | 議論の経過は議事録の仕事ではありません |
| 反対意見があったまま決まった | 決定事項に書き、`（〈名前〉より異論あり）` と1行添える | 異論があった事実まで消すと、あとで蒸し返されたときに経緯が追えない |
| メモが短すぎて3つの箱がすべては埋まらない | 埋まらない箱は「なし」と書いて残す | 箱ごと消すと、読む人は「書き忘れ」なのか「無かった」のか判断できない |
| 金額・人事・契約に関わる決定が含まれる | 議事録の末尾に「この記録は会議の要約です。正式な決定は所定の手続きでご確認ください」と1行添える | 議事録が独り歩きして、決裁の代わりに使われるのを防ぐため |

## 出力の型

```
■ 〈会議の名前〉
日時：〈開催日〉　／　出席者：〈名前を「、」で区切る〉

【決定事項】
1. 〈決まったこと〉
2. 〈決まったこと〉

【宿題】
| 内容 | 担当 | 期日 |
|---|---|---|
| 〈やること〉 | 〈名前〉 | 〈日付〉 |

【持ち越し】
- 〈結論が出なかったこと〉

次回：〈次回の予定〉

――――――
◆ 要確認（〈n〉件）
- 〈確認が必要な項目と、何が不明か〉

※ 〈金額・人事・契約に関わる決定があるときだけ、判断ルールの注意書きをここに1行入れる〉
```

**注意書きの位置は、いちばん最後（要確認の一覧のさらに下）です**（理由：本文の途中に入れると決定事項の一部に見え、末尾に置くと文書全体にかかる断り書きとして読まれるためです）。該当する決定が無い会議では、**この行ごと入れません**。

## 合格ライン（これを満たしたら完成）

- [ ] 決定事項と持ち越しが混ざっていない（決まっていないことが決定事項に入っていない）
- [ ] 宿題の全件に、担当と期日の欄が埋まっている（不明なものは `〈要確認〉` と書いてある）
- [ ] 曖昧な期日が、勝手に日付へ変換されていない
- [ ] 人の仕事ぶりへの評価が書かれていない
- [ ] 3分以内で読み終わる分量になっている（**目安：1,000字以内。超えたら、決定・宿題以外を削る**）
- [ ] `〈 〉` の穴（未確定の箇所）が1つも残っていない＝そのまま配れる状態になっている
      ※ `〈要確認〉` と `〈未記入〉` は、意図して残す印なので穴には数えません

## やってはいけないこと

- **発言をそのまま書き写さない。** 全部載せた議事録は、誰も読み返しません
- **決まっていないことを決定事項に書かない。** 「〜という方向で」は決定ではありません
- **担当者を推測で決めない。** 空欄より、間違った名前のほうが害が大きいです
- **材料に無い背景説明を足さない。** 議事録は、その会議で出た話だけでできています
- **人の仕事ぶりへの評価を書き写さない。** 「〜さんが遅い」は決定でも宿題でもありません。残るのは評価の言葉だけです
